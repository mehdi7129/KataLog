## Deux correspondances Drotek désormais prouvées

La lecture statique d’un binaire constructeur GCS a permis de reconstruire une preuve primaire, vérifiée indépendamment :

- **45008 = contrôle du show**, avec des sous-commandes de pause, reprise et démarrage.
- **45000 = réglage de la couleur des LED**.

Le `1` dans `is ok 1` n’est pas le paramètre de pause. Ce suffixe n’a pas été retrouvé dans les échantillons de firmware examinés ni dans le code public inspecté : il reste non décodé. La version exacte du firmware émetteur n’est pas attestée par l’identité du pont GCS.

Les empreintes, adresses de fonctions, symboles, recherches publiques et limites de preuve sont dans le [rapport Drotek](vendor/FOLLOWUP-20261015.md). Aucun binaire ou dump n’est distribué dans ces sources.

## Torqeedo : une source exacte retrouvée

Le [driver TQ Bus ArduPilot épinglé](https://github.com/ArduPilot/ardupilot/blob/b032bcbde31a8649d748baa5e5910208a76460f2/libraries/AP_Torqeedo/AP_Torqeedo_TQBus.cpp#L165-L245) contient le même texte `charging temp error` pour le code 48 et le même format de message. Les seuils propres à ces modèles restent dans les références ; ils ne sont pas appliqués comme seuils universels à cette installation.

Les codes **50 et 54 ne sont pas définis** dans la table de ce driver ni dans les manuels examinés. La filiation exacte avec la passerelle Drotek reste à établir. Ces codes demeurent explicitement inconnus. Le [rapport Torqeedo](marine/FOLLOWUP-20261015.md) documente les modèles, manuels, protocole et chaîne de transport CAN vérifiés.
