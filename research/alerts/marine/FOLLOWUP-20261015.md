# Torqeedo et maintien de position — recherche du 15 octobre 2026

## Résultat utilisable dans KataLog

- `err:48 charging temp error` : température de batterie incompatible avec la charge. Le sens est corroboré ; le modèle exact et les seuils de cette installation restent inconnus.
- `err:50` et `err:54` : **sens exact inconnu**. La recherche n’a pas établi leur définition pour la passerelle concernée. Ces messages passent de `interpretation` à `unresolved` et ne doivent pas compter comme des erreurs décodées.
- `Reset loiter position` : le point utilisé pour le maintien de position est réinitialisé. Ni le déclencheur ni la nouvelle position ne sont fournis.

Les trois textes principaux restent courts (au maximum 122 caractères). Les précisions de protocole et de compatibilité sont conservées dans `technicalDetails`, séparées du sens court. Les IDs restent identiques. Le motif réunissant 50/54 est scindé en deux motifs ancrés, avec un matching équivalent, pour associer exactement un exemple à chaque pattern. Un exemple synthétique pour `err:54` complète celui de `err:50`.

## Une correspondance de code source retrouvée

Révision ArduPilot consultée et figée : `b032bcbde31a8649d748baa5e5910208a76460f2`.

Le [driver TQ Bus, lignes 165–245](https://github.com/ArduPilot/ardupilot/blob/b032bcbde31a8649d748baa5e5910208a76460f2/libraries/AP_Torqeedo/AP_Torqeedo_TQBus.cpp#L165-L245) associe 48 au libellé **« charging temp error »**. Il produit le même format textuel `Torqeedo: err:…`. Sa table ne traduit ni 50 ni 54 : ces valeurs produisent seulement leur numéro.

Le [décodage, lignes 394–417](https://github.com/ArduPilot/ardupilot/blob/b032bcbde31a8649d748baa5e5910208a76460f2/libraries/AP_Torqeedo/AP_Torqeedo_TQBus.cpp#L394-L417), lit un code maître sur un octet. Les [structures, lignes 195–278](https://github.com/ArduPilot/ardupilot/blob/b032bcbde31a8649d748baa5e5910208a76460f2/libraries/AP_Torqeedo/AP_Torqeedo_TQBus.h#L195-L278), distinguent ce code des flags moteur. Cette source ne justifie donc pas de décomposer 50 ou 54 en bits.

La chaîne de transport est cohérente avec un message reçu via UAVCAN : [GCS.h, lignes 1305–1323](https://github.com/ArduPilot/ardupilot/blob/b032bcbde31a8649d748baa5e5910208a76460f2/libraries/GCS_MAVLink/GCS.h#L1305-L1323), redirige les textes vers la sortie CAN en AP_Periph. [can.cpp, lignes 1897–1958](https://github.com/ArduPilot/ardupilot/blob/b032bcbde31a8649d748baa5e5910208a76460f2/Tools/AP_Periph/can.cpp#L1897-L1958), les encapsule dans `uavcan.protocol.debug.LogMessage` et convertit notamment CRITICAL en ERROR.

**Portée de la preuve :** correspondance de format et implémentation publique identifiée. Aucune identité binaire, version ou filiation exacte avec la passerelle Drotek n’est établie. La chaîne ci-dessus explique une origine possible ; elle n’atteste pas le firmware de l’installation.

## TQ Bus, TorqLink et passerelles : éviter les faux rapprochements

Le [header du driver](https://github.com/ArduPilot/ardupilot/blob/b032bcbde31a8649d748baa5e5910208a76460f2/libraries/AP_Torqeedo/AP_Torqeedo_TQBus.h#L15-L36) décrit le TQ Bus sur RS-485 et cite Ultralight, Cruise 2.0 R/4.0 R, Travel 503/1003 et Cruise 10 kW. Il indique que des détails supplémentaires sont fournis par Torqeedo sous NDA. Cela ne permet pas de déterminer le modèle réel à partir de la seule ligne de log.

Les manuels [Display Gateway 1966-00/1968-00](https://media.torqeedo.com/downloads/manuals/1966-00-1968-00-torqeedo-manual-display-gateway-twin.pdf) et [External Access Gateway 7017/7018/7019](https://media.torqeedo.com/039-00627_External_Access_Gateway_7017-00_7018-00_7019-00_de_en.pdf#page=34) décrivent notamment TorqLink et NMEA 2000. Le second annonce un PGN propriétaire de défauts 130817, sans livrer la table utile de codes 50/54. Ni l’un ni l’autre n’atteste la passerelle UAVCAN Drotek. Les tables d’autres protocoles ne sont donc pas appliquées.

## Ce qui manque encore pour décoder 50 et 54

Il faut identifier le modèle moteur/batterie et le firmware de la passerelle, puis obtenir la définition des codes maîtres de cette combinaison. Les messages voisins peuvent aider à dater le défaut et à mesurer son effet, mais ne remplacent pas cette table. Aucune pièce, cause thermique, sous-tension ou surintensité n’est attribuée à 50/54 par hypothèse.

Les recherches exactes sur le Web (`Torqeedo err:50`, `err:54`, `E50`, `E54`, variantes avec espaces), sur les domaines constructeur et dans le driver public n’ont pas produit cette définition. Cette absence de résultat n’est pas une preuve que ces codes n’existent pas.

Le texte exact de `boat_pos_control` n’a pas été retrouvé dans une source publique primaire. La fiche reste une lecture du texte, sans prétendre connaître son déclencheur. Le projet local Aqua a seulement été consulté en lecture après ses consignes ; aucun matériel ni service réseau n’a été interrogé et aucun fichier de ce projet n’a été modifié.
